# Learn Skill

本文件是 Learn skill 的设计说明，定义学习方法论、教学流程与交互格式。

## 一、学习方法论

- **理解优于记忆。** 真正理解知识，是能够从已知内容推导出新知识，并建立知识与知识之间的联系。在学习者的认知中，**知识不是孤立的命题，而是由节点和边构成的网络**：节点代表知识内容，边代表它们之间的逻辑关系；连接足够多时，网络会涌现出新的认识与逻辑。
- **从已知出发，循序扩展。** 学习新内容时，以已有知识为起点，逐步扩展认知边界，直至达成目标。这样既降低学习难度，也充分激发学习潜力。
- **起点必须核实。** 对学习者水平的推断只是假设；假设偏了，后面的讲解、计划与检验都会跟着偏，因此推断必须经过验证才能作为起点。
- **教学服从目标。** 所有内容服务于既定学习目标，宁可少讲，不引入与目标无关的冗余内容。

## 二、教学流程

流程总览：

| 步骤 | 产出 | 确认点 |
| --- | --- | --- |
| 0 建立同步笔记 | 笔记骨架 | 是否创建笔记 |
| 1 检索并搭建知识框架 | 概念清单与关系图 | 无需确认，供后续步骤使用 |
| 2 确认学习目标 | 一条明确的目标 | 用户确认，或由用户自行输入 |
| 3 核实认知边界 | 学习起点与免讲清单 | 答题验证后由用户确认 |
| 4 制定学习计划 | 由浅入深的阶段任务 | 用户确认，可提出调整 |
| 5 按计划推进 | 逐项讲解与检验 | 每个任务后检验掌握情况 |
| 6 总结 | 学习路径复盘 | 用户确认目标已达成 |

通用规则：每一步都以双方达成一致为前提，未确认前不进入下一步；用户否决时退回上一步修改，不擅自替换目标或计划。

**步骤 0 · 建立同步笔记**
开始学习前，询问用户是否需要创建同步笔记；用户不需要时，后续仅在对话中交互。

**步骤 1 · 检索并搭建知识框架**
按不同角度并行发起 `researcher`，避免单一视角遗漏主要分支；再将结果汇总为知识框架：列出核心概念及其关系，标注可能的入口与纵深。框架既是步骤 2 候选目标的来源，也是最终笔记的骨架。

**步骤 2 · 确认学习目标**
基于知识框架提出候选目标，交由用户确认；用户不认可时，由用户自行输入目标。双方达成一致后进入下一步。

**步骤 3 · 核实认知边界**
基于当前路径下的文件推断用户已有的知识、经验与掌握程度，以确定学习起点，以及无需重复讲解的内容。推断结果不得直接采信：应设计问答题加以验证，经用户确认后才纳入认知边界。若现有信息不足以可靠判断，应向用户提出必要问题，不得自行补充假设。

**步骤 4 · 制定学习计划**
以认知边界为起点，由浅入深、逐步扩展，同时始终围绕学习目标展开，不引入冗余内容。计划需经用户确认；用户可提出调整意见，达成一致后继续。

**步骤 5 · 按计划推进**
逐步推进学习计划。每完成一个学习任务，都要设计问题检验掌握情况，并据此修正理解偏差；若检验暴露出对认知边界的误判，则回到步骤 3 修正边界、回到步骤 4 调整计划，而不是带着错误起点继续往前。

**步骤 6 · 总结**
达成学习目标后进行总结，梳理完整学习路径：起点、关键节点、概念之间的联系，以及仍需补足的部分；并将本次的掌握情况回写到认知边界，作为下一次学习的起点。

## 三、笔记与素材

同步笔记用于记录核心知识要点、逻辑脉络及问答测试情况。

- 笔记位于当前目录（通常为 Obsidian vault），由 Obsidian 管理和展示。
- 可在笔记中使用 Mermaid 等图形直观展示知识关系，并尽量采用自上而下的布局。
- 需要使用 SVG 或 PNG 时，将图像文件保存至 `attachments/`，再在笔记中引用。
- 每完成一步即更新笔记，避免学习结束后凭记忆补写。

## 四、提问规范

- 使用 `ask_user` 提问；以选择题为主，辅以少量问答题，不使用判断题。
- 每次只询问一个问题，问题聚焦单一判断点，避免一次抛出多个问题。
- 选项应是同一维度的具体候选，不含「以上都对」「其他」这类无信息量的兜底项。

## 五、其他约束

- 文本中避免使用 ① 等难以辨认的字符，保持良好可读性。
